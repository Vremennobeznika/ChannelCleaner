# Правила разработки ChannelCleaner
1. Изучить README.md, QA_REPORT.md, PUBLISHING.md, scanner.js, background.js, profiles.js, content.js, tests. Не принимать заявления из переписок за подтверждённое API Telegram.
2. Не добавлять реальные bot token, cookie, списки участников и числовые Telegram ID в GitHub или тестовые логи. Права администратора — только на тестовый канал при проверках.
3. Любое массовое удаление считается действием повышенного риска: dry-run по умолчанию; явная проверка выбранного канала и числового ID, ограничение количества, подтверждение, стоп и журнал.
4. Нельзя выводить «неактивен в канале» из «last seen a long time ago»; этот индикатор не доказывает чтение канала и может зависеть от приватности.
5. Поиск и предпросмотр должны работать без доступа на удаление. Нельзя включать автоматическое удаление при неизвестной разметке Telegram Web, отсутствии числового ID или неоднозначности.
6. Регрессия: tests/test_policy.js, tests/test_removal.js, tests/test_background.js, tests/test_profiles.js, browser mock/E2E в тестовом канале. Фактический release gate включает живой тест и проверку подтверждения.
7. Документировать точные команды/exit code/commit, отсутствие настоящего тестирования отмечать NOT VERIFIED. Скрипты и APK из Telegram-архивов не запускать вслепую.
